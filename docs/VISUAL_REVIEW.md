# Visual review: purchase to access

Independent engineering prototype. Synthetic child records. Simulated payments. Not affiliated with Nanit.

## How it was checked

- `python proof-layer/scripts/visual_qa.py access` ran against the demo server on 2026-10-11.
- **Scope:** 20 scenes × 7 viewports = 140 captures, in Chromium (Playwright), with reduced motion (final run 2026-10-11). It adds:
  - `customers` and `access-ended`;
  - the renewal journey: `renewal-ended`, `renewal-renewed` and `renewal-xray`.
- **Text under 14 px on the ended screens:** 1% at desktop. That is the 12 px "simulation" label on the developer-only demo bar.
- **Viewports:** 1280×800, 1366×768, 1440×900, 1536×864, 1920×1080, 390×844, 768×1024.
- **How state was set:** through the real API and the Scenario Studio endpoints. Nothing was mocked in the page.
- **Outputs:** metrics and screenshots are in `artifacts/visual-qa/access/`. Only the 1440×900 images are committed (`.gitignore`); the others are regenerated by the same command.
- **Screens I looked at myself:**
  - 1440×900: home, journey, connect, verified, refused lookup, studio, growth.
  - 390×844: home, journey, connect sheet.
- **Not reviewed by eye:** the remaining images, measured only.

## Measured, explained, not changed

- **X-Ray covers the page below 1280 px** (390 and 420 px wide). This is by design: it is a sheet with a scrim and a focus trap there, and it docks beside the page from 1280 px.
- **One 404 per viewport in the console.** The app's own resets (Studio, Customer evidence) no longer cause one: the poll pauses while the page resets. The remaining 404 is reproduced and explained:
  1. The script resets the data while a page is still open.
  2. That page's next poll asks for the old night: `GET /v1/windows/{old}/brief` returns 404.
  3. The app then shows its "This demo was reset from another screen" banner.
  4. Normal page loads produced no 4xx (checked separately).
